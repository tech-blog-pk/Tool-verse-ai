What Is Plugin4Shell? The Zero-Click Flaw Hitting Claude Code, Codex, Copilot & Gemini CLI

TV
ToolVerse AI
ToolVerse AI Contributor
📅 Sep 21, 2026⏱ 8 min read
🐛

Security researchers just disclosed a flaw that undermines one of the most trusted safety mechanisms in AI-assisted coding: pinning a plugin to a specific, reviewed version of its code. The flaw, nicknamed Plugin4Shell, affects four of the most widely used AI coding agents — Anthropic's Claude Code, OpenAI's Codex, GitHub Copilot, and Google's Gemini CLI — and can let an attacker run their own code on a developer's machine without a single click. This guide explains, in plain English, what Plugin4Shell is, how it works, and what you should do about it.

💡
Quick summary: Plugin4Shell lets someone who controls a plugin's code repository quietly swap in malicious code, even after that plugin was reviewed and "locked" to a specific, safe version. Claude Code and Codex are already patched; GitHub Copilot and Gemini CLI are not.

What Is Plugin4Shell?

Plugin4Shell is a high-severity, zero-click remote code execution (RCE) vulnerability discovered by researchers at AIR Security. It doesn't target the AI models themselves — it targets the software supply chain behind the coding agents that developers use every day. Modern AI coding agents let you install plugins, skills, and extensions from community marketplaces to extend what the agent can do. The problem is that these add-ons typically run with the same permissions as the developer using the agent, including access to source code, cloud credentials, SSH keys, internal repositories, and sometimes production systems.

How Does It Work?

To keep plugins safe, marketplaces normally use a process called SHA pinning: once a plugin is reviewed at a specific Git commit, that commit's unique hash (SHA) is recorded, so the agent always installs that exact, audited version — even if the plugin's repository changes later.

Plugin4Shell breaks that guarantee. For Claude Code, Codex, and GitHub Copilot, researchers found that an attacker who controls the plugin's repository can create a branch whose name is identical to the pinned commit hash. Because of how Git resolves references, it can prioritize that matching branch name over the actual pinned commit during checkout. The agent installs whatever code sits on that branch — while still reporting that it installed the expected, "safe" hash.

Gemini CLI has a slightly different version of the same underlying problem. It fetches the intended commit and then checks out something called FETCH_HEAD. An attacker can name their default branch FETCH_HEAD, which redirects the checkout to their malicious content instead of the commit that was actually reviewed.

It becomes a zero-click issue because several of these agents can automatically refresh installed plugins from their marketplaces. That means a plugin a developer already trusts — and already approved — can be silently swapped out during a routine update, with no new install prompt and no obvious warning sign.

Which Tools Are Affected?

  • Anthropic Claude Code — patched in version 2.1.179
  • OpenAI Codex — patched in version 0.146.0
  • GitHub Copilot — no fix shipped by Microsoft as of disclosure
  • Google Gemini CLI — Google has deprecated Gemini CLI rather than patching it, and is directing users to its newer Antigravity CLI instead
⚠️
Why this matters even if you're careful: This isn't about installing plugins from shady sources. The flaw affects plugins that were properly reviewed and pinned exactly as the security model intends — doing everything "right" doesn't protect you on unpatched agents.

What Should Developers Do Right Now?

  • Update immediately if you use Claude Code or Codex — run claude --version or codex --version and confirm you're on 2.1.179 / 0.146.0 or later
  • Audit your installed plugins across every agent you use, and note which ones came from marketplaces you don't personally control
  • Turn off automatic plugin updates where your agent allows it, until you can verify the exact commit hash currently installed — this removes the "zero-click" element of the attack
  • Treat GitHub Copilot plugin marketplaces with extra caution for now, since Microsoft had not shipped a fix at the time of disclosure
  • Migrate away from Gemini CLI if you rely on it heavily, since Google has confirmed it won't be patched

Why This Story Matters

Plugin4Shell is a reminder that as AI coding agents gain more autonomy and deeper access to a developer's machine, the security of the ecosystem around them — marketplaces, plugin updates, and version-pinning systems — matters just as much as the safety of the underlying AI model. A compromised plugin doesn't need to "hack" anything; it simply runs with whatever access the developer already has, which for many teams includes source code, cloud credentials, and production systems.

FAQ — Plugin4Shell Explained

Do I need to stop using Claude Code or Codex?

No — both have shipped fixes. Just make sure you've updated to Claude Code 2.1.179 or later, or Codex 0.146.0 or later.

Is GitHub Copilot safe to use right now?

Copilot itself remains usable, but its plugin marketplace carried unpatched exposure to this specific flaw at the time of disclosure — reviewing which plugins you have installed and limiting automatic updates is the safest approach until Microsoft ships a fix.

Does this affect people who don't install any plugins?

The vulnerability specifically involves the plugin installation and update process, so developers who don't use third-party plugins, skills, or extensions with these agents are not exposed to this particular flaw.

Why is it called "zero-click"?

Because affected agents can automatically refresh already-installed plugins from their marketplaces, a plugin you approved once can later be swapped for malicious code during a routine update — with no new prompt, click, or reinstall required from you.

Why won't Google patch Gemini CLI?

Google has deprecated Gemini CLI in favor of its newer Antigravity CLI and is directing users to migrate rather than issuing a fix for the older tool.

Conclusion

Plugin4Shell shows that even a security mechanism as widely trusted as commit-hash pinning can be quietly defeated when the underlying tools don't fully verify what actually got checked out. If you use any of these four AI coding agents, the fix is straightforward: update where a patch exists, and audit and restrict plugin auto-updates where it doesn't. As AI coding agents become a permanent part of how software gets built, keeping the supply chain around them secure is just as important as the capabilities of the AI itself. 🐛
