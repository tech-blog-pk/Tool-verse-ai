A Hidden File in Your Downloads Folder Can Hijack Your AI Coding Agent

TV
ToolVerse AI
ToolVerse AI Contributor
📅 Oct 27, 2026⏱ 7 min read
📂

If you use an AI coding agent like Claude Code, OpenAI's Codex, or Cursor, there's a decent chance you've opened one directly inside your Downloads folder at some point — maybe to sort through new files, or act on something you just downloaded. Security researchers just showed exactly why that habit is more dangerous than it sounds.

What researchers found

Forever Security, a firm that tracks risks specific to AI agents, discovered the technique after noticing a coding agent on a customer's computer attempting to install a suspicious npm package called function-color. Tracing the cause backward led them to a planted file sitting quietly in the customer's Downloads folder.

That file was an AGENTS.md — a plain-text instruction file that AI coding agents are designed to automatically read and follow when they're launched inside a folder containing one. It's a legitimate, useful feature in normal circumstances, meant to give an agent context about a project. The problem is that it doesn't ask who wrote the file before following it.

How the attack actually works

  1. The file gets dropped. A malicious AGENTS.md (or a similarly named file like CLAUDE.md) lands in your ~/Downloads folder. Researchers note a webpage can silently trigger this kind of download — Chrome, Edge, and Firefox all save downloads there by default (though they do show a notification; Brave asks for approval first).
  2. You launch your coding agent there. Many people start their AI coding agent directly in the Downloads folder — to organize it, inspect a new file, or just because it was the active folder at the time.
  3. The agent reads and follows the planted instructions. Because agents automatically load instruction files from their working directory, it reads the malicious file and acts on it — which can include running commands, installing packages, or changing settings, often with little or no extra confirmation.

How bad is it, really?

The researchers tested this against real tools, not just theoretically:

  • OpenAI Codex: A harmless proof-of-concept payload (simply opening the calculator app) succeeded in 90% of test runs.
  • Claude Code: A malicious CLAUDE.md file redirected the agent's API traffic to an attacker-controlled server, exposing its OAuth authentication token in the process. That server could then impersonate the AI model itself and send back tool calls that actually executed code — this worked in roughly 50% of test runs.

This isn't a hypothetical risk, either. Forever Security's internal data shows hundreds of customers already run Claude Code, Codex, and Cursor CLI directly from their Downloads folder — and Claude Code alone had logged more than 1,300 sessions launched from that exact location.

Why there's no simple "patch" for this

Here's the uncomfortable part: the researchers argue there's genuinely nothing for OpenAI or Anthropic to fix with a software update. The AI agent is doing precisely what it was built to do — read instruction files in its working directory and act on them. The actual vulnerability is the combination of two separately reasonable behaviors: browsers quietly saving files to a predictable folder, and agents trusting instruction files in whatever folder they're launched from. Neither behavior is a bug on its own. Put them together, and you get an attack surface that currently has no vendor-side fix — which puts the responsibility for defense squarely on how you, the user, choose to run these tools.

How to protect yourself

  • Never launch an AI coding agent from your Downloads folder or your home directory. Always start it from inside a specific, intentional project folder.
  • Keep the agent's working area as narrow as possible. Only expand its access to a folder when you actually need it to work there.
  • Check unfamiliar AGENTS.md, CLAUDE.md, or similar instruction files before trusting them — especially if you didn't create the folder's contents yourself or just downloaded something from an unfamiliar source.
  • Keep approval prompts and sandboxing enabled in your coding agent's settings rather than switching to a fully autonomous "just do it" mode for convenience.
  • Test unfamiliar or untrusted code in an isolated environment (a virtual machine or disposable container), not on your primary computer.

FAQs

Which AI coding agents are affected by this?

Researchers reproduced the attack directly against OpenAI Codex and demonstrated a related version against Claude Code. Their data shows Cursor CLI users launching from Downloads as well, though the specific exploit wasn't detailed for that tool in the same way.

Is this a bug that Anthropic or OpenAI need to patch?

Researchers say no — the agent is behaving exactly as designed by reading and following instruction files in its working directory. The risk comes from the combination of normal browser download behavior and normal agent behavior, not a flaw in either one individually.

How does a malicious file end up in my Downloads folder in the first place?

Researchers note that a webpage can trigger a silent download in most browsers, which saves to the Downloads folder by default. You may not notice unless you're specifically watching for the download notification.

What's the single most effective fix?

Simply never launching your AI coding agent with your Downloads folder (or home directory) as its working directory. Always point it at a specific project folder instead.

Conclusion

This isn't a flashy zero-day exploit — it's something closer to leaving your front door unlocked because it's convenient. AI coding agents are built to trust the instructions sitting in whatever folder you point them at, and most people's Downloads folder is exactly the kind of messy, unverified space that shouldn't have that trust extended to it. The fix costs nothing and takes no technical skill: just stop launching your coding agent from Downloads. 📂
