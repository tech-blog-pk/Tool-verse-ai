Building AI-Powered React Apps in 2025

PS
Priya Shah
ToolVerse AI Contributor
📅 May 7, 2025⏱ 6 min read
⚛️

Adding AI to a React app sounds deceptively simple — call an API, show the result. But production-ready AI features are a different story. You need streaming, error boundaries, loading states, rate limiting, and cost management. Here's how to do it properly.

The Right Architecture

The most common mistake developers make is calling the LLM API directly from their React components. This exposes your API key in the client bundle, has no rate limiting, and makes testing painful. The correct pattern is always to go through your own backend.

⚠️
Never expose your API key in frontend code. Always proxy through your own backend — a simple Express server, Next.js API route, or serverless function is enough.

Setting Up Streaming Responses

Streaming is the single most impactful UX improvement you can make for AI features. Instead of waiting 5–10 seconds for a full response, the user sees text appearing character by character — like watching someone type in real time.

JavaScript 
// Server-side: Next.js API route with streaming
export async function POST(req) {
  const { prompt } = await req.json();

  const stream = await anthropic.messages.stream({
    model: "claude-sonnet-4-6",
    max_tokens: 1024,
    messages: [{ role: "user", content: prompt }]
  });

  return new Response(stream.toReadableStream());
}

The useAI Custom Hook

Encapsulate all AI state in a custom hook. This keeps your components clean and makes the AI logic reusable across your app. The hook handles loading state, error state, the streamed content, and the abort controller for cancellation.

JavaScript 
function useAI() {
  const [content, setContent] = useState("");
  const [loading, setLoading] = useState(false);
  const [error, setError]   = useState(null);

  const generate = async (prompt) => {
    setLoading(true); setContent(""); setError(null);
    try {
      const res = await fetch("/api/ai", {
        method: "POST",
        body: JSON.stringify({ prompt })
      });
      const reader = res.body.getReader();
      const decoder = new TextDecoder();
      while (true) {
        const { done, value } = await reader.read();
        if (done) break;
        setContent(prev => prev + decoder.decode(value));
      }
    } catch(e) { setError(e.message); }
    finally { setLoading(false); }
  };

  return { content, loading, error, generate };
}

Cost Management Tips

Token costs add up fast in production. Here are the most effective ways to keep costs under control:

  • Always set max_tokens explicitly — never let it default to the model maximum
  • Cache responses for identical prompts using SWR or React Query with a hash key
  • Add client-side rate limiting to prevent accidental abuse during development
  • Use smaller models for simple tasks — save the big models for complex reasoning
  • Log token usage per request so you can see where your costs are going

Error Handling in Production

LLM APIs fail in ways that are different from regular APIs. You'll encounter rate limits, context length errors, content filter triggers, and occasional timeouts. Your error handling needs to account for all of these. Always implement exponential backoff for rate limit errors, and display friendly messages for content filter rejections.
