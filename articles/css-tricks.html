Modern CSS Tricks Every Developer Should Know

MR
Max Rivera
ToolVerse AI Contributor
📅 May 3, 2025⏱ 5 min read
🎨

CSS has undergone a quiet revolution over the last two years. Features that developers begged for since the early days of the web have finally landed — and they're now supported in all major browsers. Here are the ones that will actually change how you write CSS.

Container Queries — The Real Responsive Design

For fifteen years, media queries were our only tool for responsive design. The problem: they respond to the viewport, not the component's own container. This made truly reusable components nearly impossible. Container queries solve this.

CSS 
/* Make a container query-aware */
.card-wrapper {
  container-type: inline-size;
  container-name: card;
}

/* Style the card based on its OWN container width */
@container card (min-width: 400px) {
  .card {
    display: flex;
    flex-direction: row;
    gap: 24px;
  }
}

@container card (max-width: 399px) {
  .card {
    flex-direction: column;
  }
}

The :has() Selector — The Parent Selector We Always Wanted

:has() is arguably the most powerful CSS selector ever added to the language. It lets you style an element based on what it contains — something that was previously only possible with JavaScript.

CSS 
/* Style a form that contains an invalid input */
form:has(input:invalid) {
  border-color: red;
}

/* Style nav when it has an active link */
nav:has(.active) {
  background: var(--highlight-bg);
}

/* Card that contains an image gets different padding */
.card:has(img) {
  padding-top: 0;
}

Cascade Layers — End the Specificity Wars

Specificity conflicts are one of the most frustrating parts of working with CSS in large projects. @layer lets you define an explicit ordering for your styles, so you always know which rule wins — regardless of specificity.

CSS 
/* Declare layer order — later layers win */
@layer reset, base, components, utilities;

@layer reset {
  * { box-sizing: border-box; margin: 0; }
}

@layer components {
  .btn { padding: 8px 16px; border-radius: 6px; }
}

/* Utilities always win, regardless of specificity */
@layer utilities {
  .mt-0 { margin-top: 0 !important; }
}

Native CSS Nesting

You no longer need Sass or PostCSS for nesting. Native CSS nesting is supported in all modern browsers and lets you write more organized, scoped styles without a build step.

CSS 
.card {
  background: var(--bg-card);
  border-radius: 12px;

  /* Nested selectors — no Sass needed */
  &:hover {
    transform: translateY(-4px);
  }

  & .card-title {
    font-size: 1.2rem;
    font-weight: 700;
  }

  @media (max-width: 600px) {
    padding: 16px;
  }
}

Key Takeaways

  • Use container queries for components that need to adapt to their context, not just the viewport
  • :has() replaces most JavaScript used purely for adding/removing CSS classes
  • @layer is the permanent solution to specificity conflicts in large codebases
  • Native nesting means you can ditch Sass for most projects today
