Claude Code’s “Don’t Ask Again” Button Has Been Leaking Developers’ Passwords to Public GitHub

TV
ToolVerse AI
ToolVerse AI Contributor
📅 Nov 9, 2026⏱ 7 min read
🔑

If you use Claude Code, you've probably clicked "Yes, and don't ask again" to stop being interrupted for the same command over and over. It's convenient. Security researchers at Apiiro just showed that it can also quietly write your passwords and API keys into a file that many developers then push to public GitHub repositories.

What the feature does

By default, Claude Code asks permission before running most shell commands. When you pick "Yes, and don't ask again," it saves an allow rule to a file called .claude/settings.local.json inside your project, so matching commands run without prompts in future sessions. The rule covers whatever the prompt offered: sometimes a pattern like npm test *, sometimes one exact command.

Where the secrets come from

The problem is the exact-command case. If you approve a command that has a password or token typed into it, Claude Code saves the full command as plain text, secret included. Apiiro reproduced this with the latest models.

Claude Code does try to keep this file out of git by adding it to your global git excludes, but that only protects your own machine. It doesn't help if the file was already committed, and Claude Code never adds the file to the project's own .gitignore. In 539 of the 1,105 repositories researchers traced, a commit co-authored by Claude had changed the file.

How big is the leak?

  • 104,185 copies of the file were found across 103,617 public GitHub repositories
  • 1,122 copies (about 1.1%) contained at least one secret, totaling 1,379 distinct secrets
  • Over a third of those secrets open databases directly, including 379 database passwords
  • 43 SSH logins for public servers, 42 tokens for GitHub, GitLab, and npm, and 23 AWS keys
  • 63 organizations are among the file owners
  • Counting older file versions, .claude/settings.json files, and saved chat logs, the total rises to 2,539 secrets across 1,994 repositories

The researchers did not test whether every secret still works, though one notified company confirmed its key was live. Common secret scanners also miss a lot of these: Gitleaks flagged 564 of the 1,122 files and TruffleHog flagged 643, while 215 were caught by neither.

Anthropic's response so far

According to the research, an August 2025 bug report describing this behavior was closed by an automated bot as "not planned" after 60 days of inactivity. Four related reports have since been closed the same way, and the researchers say Anthropic has not replied to any of them. As of publication, no fix had been announced.

The 6-step fix for developers

  1. Search your repos. Look through your GitHub organization for both .claude/settings.local.json and .claude/settings.json, including git history, not just the current files.
  2. Rotate first, clean up second. Change every password, token, and key those files have ever contained. Deleting the file doesn't help if the secret was already copied.
  3. Stop tracking the file. Run git rm --cached .claude/settings.local.json and add it to your project's .gitignore.
  4. Clean local copies. Delete any saved rule that contains a secret, even in files you haven't committed.
  5. Keep secrets out of commands. Use environment variables or a secrets manager (for example $DB_URL) instead of typing literal passwords into a command.
  6. Approve patterns, not exact commands. Choose a pattern like Bash(npm run:*) rather than approving a single full command that may contain sensitive text.

Security teams should also treat agent folders like .claude/ the same way they treat .env files, and make sure their secret scanning can catch passwords hiding inside saved commands.

FAQs

Does this affect every Claude Code user?

No. The leak needs three things together: you approved an exact command containing a secret, you chose "don't ask again," and the settings file later ended up in a public repository.

Is my GitHub repo exposed right now?

Check. Search your repositories, including history, for .claude/settings.local.json and .claude/settings.json, and rotate any secret you find.

Is it enough to delete the file and push again?

No. Old commits keep the content, and anyone may already have copied it. Rotate the credentials first.

Do other AI coding tools have the same problem?

This research covers Claude Code only. But any tool that saves approved commands to a project file deserves the same caution.

Conclusion

A button designed to save you a few seconds can quietly turn a password into a permanent line in a file that is easy to commit by accident. The fix is cheap: keep secrets out of commands, approve patterns instead of exact strings, and ignore the .claude/ folder in git. If you've used "don't ask again" with anything sensitive, check your repos today. 🔑
